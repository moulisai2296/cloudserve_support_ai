Normalise · src/ingest.py

Validates the ticket and creates a shared representation across four channel formats. process_ticket passes only operational fields into the graph.

State: ticket ID, channel, clean text, customer context. Dataset labels and historical outcomes are reserved for evaluator scoring.

Routing precedence

  1. Emergency kill switch
  2. Security, compliance, residency intents
  3. Content exclusions / feature request
  4. Enterprise + high urgency
  5. Unclear request
  6. Classification confidence below 0.80
  7. No relevant documentation

Otherwise: generate a draft. The kill switch is checked after retrieval and classification, not at ingress.

Trust and data boundaries

Runtime inputs

Ticket text and operational customer metadata enter normalisation and inference. External channel connectors are not implemented.

External model provider

Model-enabled classification and generation use OpenRouter. Local embeddings do not make the whole workflow local.

Local persistence

Chroma retains indexed passages. SQLite retains decision records. Neither is a demonstrated production access-control or retention system.

Evaluation only

Intent, urgency, expected route, expected source IDs, must-not-auto labels, and history remain outside runtime routing.

Audit and failure handling

The harness associates every input with a run ID and input position. Reconciliation checks the exact expected records, including repeated ticket IDs at different positions. Historical records cannot cover a missing decision in the current run.

Input / processing failure

Attempt a logged escalation for that record, then continue the batch.

Audit write failure

Record incomplete audit status and fail the run's exit status. Continuing does not mean passing.

Offline execution

Heuristic classification and extractive draft fallback. Separate quality and timing from hosted models.
